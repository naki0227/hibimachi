# ADR-0011: 英語対応 — 日本語を原文にした String Catalog と、漏れを止める検査

- **日付**: 2026-10-26
- **状態**: Accepted（英語の文言はネイティブ確認前）

## 背景
「英語対応」をv1.0の範囲に含めた（ユーザー選択 2026-10-26）。文言はすべて日本語の直書きで、`String` を返す表（GameText）と SwiftUI の `Text("…")` が混在していた。

## 決定
1. **日本語を原文（developmentRegion = ja）のまま、`Shared/Localizable.xcstrings` に英語を足す**。Shared/ はアプリとウィジェットの両ターゲットに入るので、1つのカタログで両方を訳す。
2. **文言の書き方のルール**:
   - `String` を返す表や計算プロパティは `String(localized: "…")`。
   - パネルの題・入力欄の案内・ダイアログの文は引数を `LocalizedStringKey` にする（呼び出し側はリテラルのまま）。
   - 三項演算子は `String(localized:)` を両側に書く（`Text(flag ? "a" : "b")` は String になり訳されない）。
3. **`scripts/check_localization.py` を docs CI で実行**し、(a) 訳されない場所にある日本語リテラル、(b) 英語のない鍵、(c) プレースホルダー数の不一致で失敗させる。
4. **`EnglishUITests` が英語で起動し、主要画面に日本語が残っていないことを確かめる**（実際に鍵が引けているかの最終確認）。日本語のUIテストは `-AppleLanguages (ja)` で言語を固定する。
5. **目標のプリセットクエストは作成時の表示言語でコピーする**。保存済みの題名は言語を切り替えても変えない（プレイヤーが編集できる「自分のデータ」だから）。英語でも件数と分数は同じで、報酬は言語に依存しない。
6. アプリ名は InfoPlist.xcstrings（ひびまち / Hibimachi）。日付は端末のロケールで表示する。App Store の en-US 情報とスクリーンショット（`-testLanguage en`）も同じ手順で作る。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| 鍵 | 日本語の原文 | 英語のID鍵（`quest.done`）: 既存の全呼び出しを書き換え、日本語の文脈がコードから消える |
| 形式 | String Catalog | .strings: 複数形・状態管理がなく、Xcode 26 の標準から外れる |
| 漏れ検査 | 静的検査＋英語UIテスト | Xcode のビルド時抽出だけ: CI では未翻訳を失敗にできない |

## リスク・見直し条件
- 英語の文言は開発者の訳。ストア公開前にネイティブの確認を入れたい。
- サポート/プライバシーのページ（enludus.com）は日本語のみ。英語圏へ配信するなら英語版を用意する。
- 検査は「日本語を含むリテラル」が対象。日本語を含まない英語の直書きは検出しない（現状は記号と数字のみ）。
