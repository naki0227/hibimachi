# ADR-0009: v1.0 の中身 — 20種の配置物、レベルか発見での解放、好みの違う住人

- **日付**: 2026-10-26
- **状態**: Accepted（数値はプレイテストで調整する前提）

## 背景
ユーザー指示（2026-10-26）「このゲーム完成させてほしい」で、範囲として「中身を増やす」「思い出と次の提案」「音と設定画面」「英語対応」を選択。
P1までは配置物7種・反応4種・住人1匹で、数日遊ぶと見るものがなくなる。ADR-0005 で `Unlock` は使わないとしていた。

## 決定
1. **配置物を20種にする**（さくら・しげみ・いわ・さく・ポスト・ピクニックシート・巣箱・ブランコ・たき火・井戸・はたけ・ふんすい・カフェを追加）。はたけ・ふんすい・カフェは家・池と同じ2x2。
2. **解放は「レベル」か「発見数」のどちらかを満たせばよい**（`Unlocks.Requirement`）。Lv2/発見3、Lv3/発見6、Lv4/発見9 の3段。最初の7種は常に解放。
   - 目標を使わない人でも、置き方を工夫して発見を増やせば先へ進める（現実の行動だけが進行の鍵にならない）。
   - 解放前でも、手持ち（過去に買った物）は置ける。購入だけを止める。
3. **反応を15種にする**。組み合わせの反応（花のとなりのベンチ、木のそばの巣箱、木かげのピクニック、ベンチのあるカフェ）は「置き方を考える」動機として残す。
4. **住人を3種にする**（もち・ことり・こだぬき）。発見数0/3/7でやってくる。種ごとの好み（反応の重み倍率）で、同じ島でも動きが変わる。
5. **保存は schema v4**: 住人の一覧（2匹目以降）と種、配置物の `placedAt`（いつ迎えたか）。v1〜v3 は「もち1匹、迎えた日なし」として読む。
6. **建物の思い出と次の一手**: 配置物を選ぶと「M/Dに迎えた」からその日のアルバムを開ける。クエスト達成後に、次に置けそうな物・まだ見ていない反応・もうすぐ解放される物を1つだけ示す（`NextStep`、ルールのみでAIなし）。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| 解放条件 | レベル **または** 発見 | レベルのみ: クエストをしない日が続くと止まる / 発見のみ: 現実の行動とつながらない |
| 住人の増え方 | 発見数で自動 | 購入: 住人を「買う」のは世界観に合わない |
| 住人の違い | 反応の重み倍率 | 種ごとの専用反応: 数が増えすぎ、図鑑の意味がぶれる |
| 次の提案 | 1つだけ表示 | 一覧: 「やることリスト」になり、のんびり感が薄れる |

## リスク・見直し条件
- 解放と価格は暫定値。7日間テストで、3日目までに2段目へ届くかを見る。
- 住人が増えると反応の頻度が上がる。多すぎるなら `ReactionRule` の重みか住人ごとのクールダウンを足す。
- 住人の上限は3。増やすときは島の広さ（16x16）と歩ける場所の数を先に確認する。
