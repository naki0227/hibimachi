# ADR-0004: アイソメトリック表示とコード描画のピクセルアートへ切り替える

- **日付**: 2026-10-26
- **状態**: Accepted（Simulatorで確認。実機・プレイテスト未実施）

## 背景
P0デモ動画の確認後、ユーザーが目標とする画面イメージ（2026-10-26提示のモックアップ2枚）を共有した。モックアップは**アイソメトリック（斜め見下ろし）**の浮島、崖と浅瀬、細かいピクセルアート、カテゴリ別パレット（建てる／かざる／みち／しぜん）、昼夜の変化を示している。VISUAL-DIRECTION.md は「3/4視点の直交グリッドを第一候補（擬似アイソメではない）、試作で検証」としていた。

## 決定
1. **表示をアイソメトリック（2:1菱形、64x32 scene unit/タイル）に変更**。ルール側の座標（TileCoord）は変えず、投影だけを `IsoGrid`（Core、テスト可能）で行う。描画順は奥（x+yが大）→手前。
2. **アートはコード描画のピクセルアート**（`PixelCanvas` に低解像度で描き、nearest拡大。1 art pixel = 2 scene unit）。地形は島全体を1枚のテクスチャに焼き、地形が変わったときだけ再生成する。
3. **UIをモックアップ準拠に変更**: ロゴヘッダー、状態チップ、右側の丸ボタン（図鑑・一覧・時間帯）、写真付き「発見！」カード、タブ付きパレット、白いカード型パネル。
4. 追加要素: 小道を引く（草地⇔小道、Undo可）、ランプ、昼夜（端末時刻に連動し、手動プレビューも可。見た目だけでルールには影響しない）。

## 選択肢
| 案 | 利点 | 欠点 |
|---|---|---|
| **コード描画ピクセルアート（採用）** | 依存なし・完全オリジナル・すぐ差し替え可能・CIで再現できる | モックアップの描き込み密度には届かない |
| アーティストによる手描きアセット | 最も品質が高い | 制作期間と費用。P0検証前には重い |
| 画像生成AIでアセット作成 | 速い | 一貫性・透過処理・権利と出所の説明が必要。方針（独自制作）との整合をユーザーと決める必要がある |
| 直交グリッドを維持 | タップ判定が単純 | 目標イメージと離れる |

## トレードオフ / リスク
- 菱形タイルは指で狙いにくい。確定は必ずボタン、プレビューは ○/× と文章で示し、矢印キーで1マスずつ動かせる、という既存の誤操作対策を維持する。
- 16x16の島を横幅に収めると1タイルが約23ptと小さい。ピンチで拡大する前提。マップサイズと初期ズームは実機で再調整する。
- モックアップの通貨チップ（コイン・芽・花）はP1の経済設計と未整合（GAME-DESIGNは共通資源1種）。今回はチップに「置いたもの」「発見数」を表示し、通貨はP1で決める。

## 見直し条件
- 実機でタップ精度に問題が出たら、タップ範囲の拡大や拡大時のみ編集可能にするなどを検討する。
- 本番アセットの制作方法（アーティスト／生成AI＋加工）が決まったら、`IslandArt` / `ObjectSprites` をテクスチャアトラス読み込みに置き換える（ノード名・`ObjectKind` の rawValue は維持）。
