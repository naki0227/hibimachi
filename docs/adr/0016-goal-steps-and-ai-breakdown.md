# ADR-0016: 目標の3段（長期 → ステップ → 日々のクエスト）と、AIでの細分化

- **日付**: 2026-10-27
- **状態**: Accepted（ステップ数・回数の目安はプレイテストで調整）

## 背景
オーナーの構想（2026-10-27）:
- 目指すところを細分化したい。中期目標・長期目標・日々のタスクに分け、細分化されたものをクリアしていくことで成長を見えるようにしたい。

決定（AskUserQuestion、2026-10-27）:
- 細分化は「長期 → 中期 → 日々の3段」に、AI による細分化の提案も入れる。
- 成長は島に目標の建物が育つ形で見せる（建物は次の PR、ADR-0017 予定）。
- PR #5 をマージしてから新しい PR で作る。

これまでの目標は「目標 → クエスト」の2段だった。目標は最大3つまで同時に進められ、クエストは5〜15分の小さな行動だった。

## 決定
1. **3段の呼び方**
   - いまの「目標」を長期目標とする。
   - その下に「ステップ」（中期）を順番に並べる。
   - ステップごとに日々のクエストを持つ。
   - ステップのない目標は、これまでどおり2段のまま使える。
2. **ステップの達成は回数で決める**。ステップには「何回やったら次へ」の目安（1〜99回）を付ける。
   - 進み具合は、そのステップのクエストの達成回数から毎回計算し、別に保存しない。
   - このため、達成を取り消すとステップの進み具合も自然に戻る。
   - 期限（日付）は付けない。遅れても罰がないという設計方針（PRIVACY-AI「罰を与えない」）に合わせる。
3. **今のステップのクエストだけを出す**。きょうのクエストの候補は、次の2つを合わせたものから選ぶ。
   - その目標の「ステップに属さないクエスト」（いつものクエスト）。
   - 「いまのステップ（まだ終わっていない最初のステップ）」のクエスト。

   先のステップのクエストは、そのステップに進むまで出さない。
4. **細分化の提案（`PlanDraft`）**。目標の画面で「ステップに分ける」を押すと、提案が出る。
   - ステップは2〜5個、各ステップのクエストは1〜3個。
   - 提案は、本人が名前・回数を直したり、ステップを消したりしてから「これで始める」を押すまで反映しない。
   - **端末内AI**: Apple Intelligence に、決まった書式（`STEP: 名前 | 回数` と `- クエスト | 分`）で書かせる。
     - アプリ側で読み取り、件数・文字数・回数・分を範囲に収める。
     - 読めないとき、タイムアウトのとき、AIが使えないときは、カテゴリのひな形を出す。
     - 構造化出力（`@Generable`）は使わない。理由は、書式を読む処理を Linux のテストで確かめられることと、CI でマクロを含むコードを試せないこと。
   - **ひな形**: カテゴリごとに3ステップ。日本語と英語がある。
5. **作り直し**: ステップを作り直すと、古いステップは消える。
   - 古いステップのクエストは、達成の記録があれば退役（もう出さない）にし、なければ消す。履歴は壊さない。
6. **報酬は変えない**（報酬規則 v3 のまま）。ステップを終えたときの見返りは、島の建物が育つこと（ADR-0017 予定）で見せる。XP やきらめきは足さない。
7. 保存は schema v8。
   - ステップ `steps`（id, goalID, title, target）を追加する。
   - クエストに `stepID`（省略可）を追加する。
   - v7 以前はステップなしとして読める。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| ステップの達成 | 達成回数から毎回計算 | 達成日時を保存: 取り消しとの整合を別に保つ必要がある |
| 期限 | なし | 日付つきの中期目標: 遅れが「失敗」に見え、罰を与えない方針と合わない |
| AIの出力形式 | 決まった書式の文字列を読み取る | 構造化出力: CI で確かめられない |
| ステップの報酬 | なし（島の建物で見せる） | XP ボーナス: 回数を小さく設定するほど得になり、目安を正直に付ける動機を損なう |

## リスク・見直し条件
- AI の提案の質は端末で確かめるしかない（CI では、書式を読み取る処理とフォールバックだけを確かめる）。
- 回数の目安（ひな形は 7・14・21 回など）は暫定。重すぎるという声が多ければ下げる。
