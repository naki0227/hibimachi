# ADR-0005: P1の経済 — 共通資源1種・手持ち（在庫）方式・台帳から残高を算出

- **日付**: 2026-10-26
- **状態**: Accepted（数値は暫定。プレイテストで調整）

## 背景
ユーザー決定（2026-10-26）: 報酬は「全行動で手に入る共通資源1種」（モックアップの3通貨は採らない）。P1の範囲は PRD/GAME-DESIGN の「目標→小クエスト→チェック式達成→XP・共通資源→建築」。不正防止（同じ達成で二重に報酬を得られない）、苦手・得意や生活環境で不利にしない、罰しない、が条件。

## 決定
1. **通貨は「きらめき」1種**。どのカテゴリのクエストでも同じ量（基本 20 XP + きらめき 5）。挑戦・継続ボーナスはP1では入れない（公平性の検証後）。
2. **残高は台帳（RewardTransaction）の合計から算出する**。値を別に保存しないので、残高と台帳の食い違いが原理的に起きない。保存データの読み込み時に、同じ completionID への二重付与や残高のマイナスを検出したら、データ破損として扱う（退避して通知）。
3. **建物は「持ち物」方式**。買うと所持数+1、置くと1つ使う、しまうと手持ちに戻る（返金なし・無料で置き直せる）。Undoで配置を取り消しても、購入は取り消さない（手持ちに戻るだけ）。場所の検証が先で、置けない場所では何も消費しない。
4. **はじめに きらめき 30 を贈る**（新しい島、v1からの移行の両方）。P0の「すぐ置いて遊べる」体験を残すため。v1データは「置いてある物を所持している」状態に移行する。
5. **達成の取り消しは当日分だけ、かつ得たきらめきが残っている場合だけ**。打ち消しの台帳行を追加し、同じクエストを再び達成しても報酬は通算1回分になる。
6. 今日のクエストはルールベース（日付をシードに固定した並び、目標を順番に1つずつ、最大3件、「ほかの」で当日だけ入れ替え）。目標は同時に3つまで、「おやすみ」にすると枠が空く（履歴は消えない）。
7. **「島をはじめから」は島だけをリセットする**。目標・台帳・持ち物は残すので、稼いだものは失われない。
8. 保存は schema v2（v1 からは読み込み時に自動移行）。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| 通貨 | 1種 | 3種（モックアップ）: 行動の種類で手に入る物が偏り、仕様の公平性方針に反する（ユーザー判断） |
| 撤去時の扱い | 手持ちに戻す | 一部返金: 計算と端数が分かりにくく、試しに置く遊びを妨げる |
| 残高の保存 | 台帳から算出 | 残高フィールドを持つ: 台帳と不整合になりうる |
| 保存先 | 既存のJSONファイル（schema v2） | SwiftData: P1の規模（数十〜数百件）ではまだ利点が小さい（ADR-0003の見直し条件を再評価し、現状維持） |

## リスク・見直し条件
- 台帳は増え続ける（1日数行）。数年分で数万行になったら、締め処理（スナップショット行）を検討する。
- 価格（花5〜家30）とクエスト報酬5の比率は暫定値。7日間テストで「買えない不満」「余りすぎ」を見て調整する。
- 自己申告は証明ではない。連打などの不正に罰は設けない（1日1クエスト1回の上限だけを設ける）。

## 追記（2026-10-27、オーナーの指摘による変更）
オーナーの指摘（2026-10-27）は「目標を自由に消したり追加できたりしたい」。今は新たに追加できない。
- 原因: 目標が3つになると「目標を追加」ボタンが消える作りで、理由も出ていなかった。削除の手段もなかった。
- 変更内容:
  - 同時に進められる目標を **5つ** にした。
  - 上限に達してもボタンは表示したまま押せなくし、理由（おやすみか削除で枠が空く）を出す。
  - 目標を **削除** できるようにした（確認を1回はさむ）。
    - 達成記録のない目標は、クエスト・ステップごと消す。
    - 記録のある目標は、台帳・アルバム・過去の日が参照しているため、非表示（`deleted`）にとどめる。XP・きらめきは減らさない。
  - きょうのクエストを選ぶ順番の起点を、日ごとにずらす。目標がきょうのクエスト数（3件）より多いときも、どの目標にも番が回るようにするため。
- 見直し条件: 目標が多いと1つあたりのクエストが出る日が減る。「進まない」と感じる声が多ければ、上限か1日の件数を見直す。
