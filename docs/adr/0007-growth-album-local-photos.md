# ADR-0007: 成長アルバム（P2）— 任意の記録、写真は端末内の別ファイル、報酬なし

- **日付**: 2026-10-26
- **状態**: Accepted（実機での写真選択・容量・バックアップは未検証）

## 背景
ROADMAP Stage 3（P2）: 写真1枚と短文の任意保存、日付/クエスト/建築とのリンク、写真削除・容量表示、標準非公開。
PRIVACY-AI: 写真はローカル保存、最小権限、EXIF位置情報の除去。記録媒体の有無で進行に差をつけない。
ユーザー指示（2026-10-25）: 写真分析・SNS・クラウド同期は実装しない。

## 決定
1. **記録は任意で、報酬は付けない**。GAME-DESIGN の「写真・短文記録 +0〜5」は、記録しない人との公平性を検証するまで入れない。
2. **1件 = ひとこと（200字まで）と写真1枚のどちらか、または両方**。今日の達成済みクエスト1件にひもづけられる（任意）。
3. **写真はシステムの PhotosPicker で選ぶ**（写真ライブラリの権限要求なし）。カメラは使わない（権限が増えるため）。
4. **保存前に縮小とメタデータ除去**: 長辺1280pxに縮小、向きを正し、JPEGを作り直してEXIF/GPSを持ち込まない（`PhotoPrep`）。
5. **写真はアプリ専用の Application Support/<保存名>/media/<id>.jpg**。App Group（ウィジェットと共有）には置かない。保存ファイル（schema v3）にはファイル名だけを持ち、読み込み時に「単純なファイル名」以外を拒否する（改ざんでフォルダ外を指せないようにする）。
6. **アルバムの日別表示**は、その日の達成クエスト・迎えた建物・得たきらめき・記録を新しい日から並べる（`AlbumDay.history`）。
7. 削除は2回タップで確認し、保存から外してから写真ファイルを消す（ファイル削除の失敗は容量の無駄にとどまる）。「島をはじめから」でもアルバムは消えない。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| 写真の選び方 | PhotosPicker | 写真ライブラリ全体の権限: 必要以上のアクセス |
| 写真の保存場所 | 保存JSONとは別のファイル | JSONにBase64で埋め込む: 保存が重くなり、原子的書き込みのたびに全写真を書き直す |
| 写真の場所 | アプリ専用フォルダ | App Group: ウィジェットが写真を使わないので共有範囲を広げない |
| 記録の報酬 | なし | 少額ボーナス: 記録しない人が不利になる。プレイテスト後に再検討 |

## リスク・見直し条件
- 写真は端末バックアップ（iCloud バックアップ含む）の対象になる。→ 2026-10-26 ユーザー決定で「含めたまま」。
- 孤立した写真ファイル（削除失敗・保存失敗の残り）を掃除する処理はまだない。容量表示は保存内の参照の合計で、実ファイル合計ではない。
- 容量が大きくなったら（例: 100枚超）、サムネイルキャッシュや一覧の遅延読み込みを検討する。
