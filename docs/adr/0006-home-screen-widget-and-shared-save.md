# ADR-0006: ホーム画面ウィジェット — App Group で保存を共有し、ウィジェットからも達成できる

- **日付**: 2026-10-26
- **状態**: Accepted（実機・署名付きビルドでの確認は未実施）

## 背景
ユーザー要望（2026-10-26）: 「ウィジェットで使えるようにしたい。大きめのウィジェットは左に箱庭の様子、右にtodoリスト」。
ウィジェットは別プロセス（WidgetKit extension）で動く。アプリの保存（ADR-0003のJSONファイル）を読み書きできる場所に置き、島の絵を用意する必要がある。

## 決定
1. **WidgetKit extension（`HibimachiWidgetExtension`）を追加**し、アプリに埋め込む。サイズは小・中・大。大と中は「左に島、右にきょうのクエスト」、小は島と残り数。
2. **保存を App Group（`group.dev.naki0227.hibimachi`）のコンテナへ移す**。既存の Application Support の保存は初回に1度だけ移動する（新しい側に保存があるときは上書きしない。移動に失敗したら旧フォルダを使い続ける）。App Group が使えない（署名なしCIビルド等）ときは従来どおりアプリ専用フォルダを使い、ウィジェットは「アプリをひらいて」表示になる。
3. **ウィジェットは `peek()`（副作用なしの読み込み）だけを使う**。壊れたファイルの退避や新しい島の作成はアプリだけが行う。
4. **ウィジェットの「○」をタップすると App Intent でクエストを達成**する（iOS 17のインタラクティブウィジェット）。報酬規則はアプリと同じ（`QuickQuestCompletion` が `PlayerProgress.complete` を使う。1日1クエスト1回、1達成1報酬）。
5. **島の絵はアプリが描いて共有コンテナにPNGで置く**（シーンが非アクティブになる瞬間に昼の色・ライトの光なしで撮影し、最大幅640pxに縮小）。ウィジェットでSpriteKitの描画は行わない。
6. **書き込みの競合**: アプリは `.background` でだけ保存し（`.inactive` では保存しない）、`.active` に戻ったときにディスクから進捗を読み直す（保存失敗中は読み直さない）。
7. 日付が変わるとクエストが入れ替わるため、タイムラインは次の0時に更新する。アプリはバックグラウンドへ移るときに `reloadAllTimelines` を呼ぶ。

## 選択肢
| 論点 | 採用 | 不採用と理由 |
|---|---|---|
| ウィジェットのデータ | 保存ファイルをそのまま読む | アプリがウィジェット用の要約JSONを書く: 日付が変わったとき、アプリを開くまで古いクエストが残る |
| 島の絵 | アプリが撮ったPNG | ウィジェット内で描く: アートコード（SpriteKit/PixelCanvas）を両ターゲットに分ける必要があり、メモリ制限も厳しい |
| ウィジェットからの達成 | App Intent でその場で達成 | アプリを開くだけ: 「todoリスト」として使う体験にならない |
| 競合対策 | 保存の時機を限定し、復帰時に読み直す | NSFileCoordinator: 現状は「ウィジェットを触るときアプリは前面にない」ので過剰。iPadの分割表示などに対応するときに再検討 |

## リスク・見直し条件
- 開発者アカウントで App Group を登録しないと実機ではウィジェットが「アプリをひらいて」のままになる（Xcode の Signing & Capabilities で Team を選ぶ）。
- CI は署名なしでビルドするため、App Group 経由の実データ表示・ウィジェットからの達成は自動テストで確認できない。UIテストはデバッグ用プレビュー（アプリ内で同じビューを実データで描画）で見た目だけを確認する。
- 島の絵はアプリを離れた時点のもの。生き物の動きやウィジェット上での変化はない。
