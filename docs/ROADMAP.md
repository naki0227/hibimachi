# Roadmap — ゲームの面白さから検証する

## Stage 0 — Docs / CI（別コミット）
- [ ] 新規Private Repoを作り、本資料を移す。仮称HIBIMACHI、元のVault概念ノートと相互参照。
- [x] Xcodeプロジェクト（SwiftUI/SpriteKit）初期化・shared scheme。
- [x] formatter、lint、unit test、typecheck相当、buildのCI。緑になったら機能へ進む。
- [ ] アセットの命名・ファイル規則と無断転載防止チェック。

## Stage 1 — P0: 操作して楽しい箱庭
- [x] 16x16タイルマップとカメラ操作、配置パレット。
- [x] 建築物のプレビュー、自由配置、移動、撤去、undo（20段）。
- [x] 1生き物の散策、ベンチ/木/池への3つの反応＋組み合わせ反応（花の隣のベンチ）。
- [x] 保存復元、背景への移行、クラッシュしないエラー処理（実機での中断テストは未実施）。
- [x] 最小チュートリアル（置く→発見→きょうのことの3ステップ、とばせる。2026-10-26）。
- [ ] 2〜5人でゲーム単体プレイテスト。自発的な配置/再訪/発見を観察。

## Stage 2 — P1: 現実と接続
- [x] 目標テンプレートと手動の階層化、任意の自由入力（6カテゴリのプリセット＋自分のクエスト追加、2026-10-26）。
- [x] 今日の小クエストをルールで提案、選択・変更・スキップ可能（1日3件）。
- [x] ワンタップ達成、基本XP・共通資源（きらめき1種）、報酬二重防止、当日の取り消し（ADR-0005）。
- [ ] 得意/苦手の自己申告を任意に扱い、公平性/説明性を検証。
- [ ] 最小建築コレクションと経済のバランス調整（価格と持ち物方式は実装済み。数値の調整は未実施）。

## Stage 3 — P2: 成長アルバム
- [x] 写真1枚と短文の任意保存、日付/クエスト/建築とのリンク（ADR-0007、2026-10-26）。
- [x] 写真削除・ストレージ量表示、標準非公開（端末内のみ、EXIF除去）。
- [ ] 7日間テストで記録の負担と箱庭への愛着を確認。

## Stage 4 — P3: 任意AI
- [ ] Apple Foundation Modelsでの目標細分化・短文提案（対応端末）。
- [ ] ClaudeやJevは比較実験の仮説を定義してから検証。コスト・精度・プライバシーで優位性がなければ不採用。
- [ ] Image understandingは利用可能なOS/端末でのみ、本人の意思で実行。成果/努力を断定しない。

## Stage 5 — P4: 共有 / CD
- [ ] 箱庭だけの静止画像共有（写真・目標を含めない）。
- [ ] 必要に応じてクラウド同期を設計（Apple/端末バックアップの復元要件を含める）。
- [ ] TestFlight配信の手動起動（`testflight.yml` を用意。xcodebuild + API キーで asc CLI は不要。Secrets 登録後に初回実行）→安定したらタグ起点のCD。

## 見直しゲート
- P0で「タスク報酬なしではつまらない」と判断されたら、AIではなく建築/発見/住人の遊びを最優先で直す。
- P1で記録操作に疲労が出たら自動化より先にタップ数と通知設計を見直す。
- P2で写真保存の心理的ハードル/容量が大きい場合は文章・チェックの体験を優先する。
- P3でAIの追加価値が小さいなら導入しない。
